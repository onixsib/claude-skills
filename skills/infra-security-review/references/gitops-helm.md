# GitOps, Helm, ArgoCD

## Что реально доедет

- Рендерить `helm template` с теми values и в том порядке переопределений, с которыми релиз реально синкается (общие → окружение → кластер). Находка в дефолтах чарта, переопределённая на всех кластерах, — не находка; переопределение, включающее опасное только на одном кластере, — находка.
- Ветка или тег, из которого синкается кластер: изменение в `main` может не доехать, а в ветке, которую синкает прод, — доехать сразу.
- Условные блоки (`if .Values.x.enabled`) — проверить, включены ли они там, где важно.

## ArgoCD

- `AppProject`: `sourceRepos: ['*']`, `destinations` с `*` по серверу или namespace, `clusterResourceWhitelist: '*'` — проект может развернуть что угодно куда угодно.
- Роли и токены проектов: кто может синкать, срок токенов, где хранятся.
- `syncOptions`:
  - `Replace=true` — пересоздаёт объект; на CRD, Secret с CA, объектах с данными — потеря данных;
  - `Prune=true` и автосинк на ресурсах, удаление которых каскадно сносит нагрузку (namespace, CR с финализаторами);
  - `ServerSideApply`, `Force=true` — понимать, что перетирается.
- Аннотации защиты (`argocd.argoproj.io/sync-options: Delete=false`, `Prune=false`) на объектах, которые нельзя терять, — есть ли.
- `ignoreDifferences`, скрывающие дрейф в полях безопасности.
- Учётки ArgoCD с `role:admin` для автоматических систем — нужен ли полный admin.

## Helm

- Хуки (`pre-install`, `post-delete`) с Job'ами, которые трогают секреты или внешние системы.
- `lookup` в шаблонах — рендер зависит от состояния кластера.
- Секреты, сгенерированные в шаблоне (`randAlphaNum`), — меняются при каждом рендере, если не закреплены.
- Зависимости чарта без закреплённой версии; локальные чарты, скопированные из внешних источников без указания версии.

## Структура репозитория

- Ручные скрипты и ранбуки рядом с values (`*.sh`, «запустите в поде Vault под root»), создающие сущности в обход GitOps — их результат не виден в коде и не пересматривается.
- Удаление защитных настроек в диффе (снятые `securityContext`, `NetworkPolicy`, `failurePolicy`, ограничения ролей) — смотреть удалённые строки, `git log -S` по удалённому фрагменту.
