# Crossplane

## Удаление и подхват

- `deletionPolicy: Delete` (умолчание) на управляемых ресурсах, которые подхвачены из существующих (`crossplane.io/external-name`) или общие для нескольких XR, — удаление XR или смена имени снесёт внешний объект. Для подхваченного и общего: `Orphan` и `managementPolicies` без `Delete`.
- Подхват сразу в полном управлении — первый же реконсил перезапишет внешний объект значениями из композиции. Безопасный порядок: `Observe` → сверка → управление без `Delete`.
- Ресурсы, удаление которых разрушительно (auth mount Vault, namespace с нагрузкой, база): защита `Usage`/`ClusterUsage`, `Orphan`, отсутствие `Delete` в `managementPolicies` — все три, а не одно.
- Смена имени композиции, XR, ресурса в композиции — Crossplane воспринимает как новый ресурс и удаляет старый.

## Учётные данные провайдеров

- `ProviderConfig` с учёткой уровня администратора внешней системы (approle с root-эквивалентной политикой, токен admin GitLab/Harbor). Одна такая учётка на все композиции — компрометация провайдера даёт всё.
- Где лежат Secret'ы `ProviderConfig`, кто их читает (RBAC на namespace crossplane).
- Connection secrets (`writeConnectionSecretToRef`) — в каком namespace, кто их читает, не уходят ли в управляемый кластер шире нужного.

## Утечки через объекты

- `Object` (provider-kubernetes) зеркалит удалённый объект в `status.atProvider.manifest`. Для Secret проверить, что `data` вырезается; `last-applied-configuration` в статусе; значения, подставленные из Secret через `references`, не должны попадать в `spec.forProvider.manifest` открытым текстом.
- function-go-templating/extra-resources: какие Secret'ы подтягиваются в функцию (весь Secret, включая приватные ключи CA, когда нужен только сертификат).
- Логи провайдеров: некоторые версии upjet-провайдеров печатают тела секретов в debug.

## Пакеты

- Провайдеры и функции по плавающему тегу (`:v1`) — меняются без MR. Провайдер с админскими учётками — закреплять версию.
- Источник пакетов: прокси-реестр, зеркало, прямой `xpkg.upbound.io`.
